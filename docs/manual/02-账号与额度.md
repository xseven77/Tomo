# 02 - 账号与额度管理

本章介绍 Tomo 的多供应商 AI 账号连接、凭证隔离、额度/余额查询与模型探测机制。

---

## 1. 架构总览

Tomo 支持接入四类主流 AI 服务供应商：

| 供应商标识 (`ProviderID` / `AgentID`) | 认证模式 | 凭证存储位置 | 额度/用量指标 |
|---|---|---|---|
| **Codex (OpenAI)** | OAuth 2.0 PKCE（按账号隔离 CODEX_HOME） | `~/Library/Application Support/Tomo/Runtimes/Codex/<UUID>/oauth_token.json`（`AccountConnectionServices.swift:86-127`） | 5h/周限流窗口（`CodexAccountRateLimitWindow`）、重置券（`ResetCoupon`）、订阅到期（`activeUntil`）、可用模型目录 |
| **Google Gemini** | Google OAuth 2.0 PKCE | `~/Library/Application Support/Tomo/gemini_oauth/<handle>.json`（权限 0600，`GeminiOAuthService.swift:36-73`） | 额度快照 `GeminiQuotaSnapshot`（Antigravity 周度/5h、Claude·GPT 第三方周度/5h 池） |
| **DeepSeek** | API Key (Bearer) | `~/Library/Application Support/Tomo/deepseek_credentials/<handle>.json`（权限 0600，`AccountConnectionServices.swift:218-235`） | 账户余额：`total_balance` / `granted_balance` / `topped_up_balance` + 币种（`/user/balance`，`:302-330`） |
| **OpenCode (Go / Zen)** | API Key (Bearer) + 计划类型 | `~/Library/Application Support/Tomo/opencode_credentials/<handle>.json`（权限 0600，与 DeepSeek 目录物理隔离，`:340-346`） | 模型目录校验（Go: `https://opencode.ai/zen/go/v1/models`，Zen: `/zen/v1/models`，`:455-471`） |

> 注：Keychain 目前用于 **Gateway 侧密钥托管**（`GatewaySecretBroker`，`GatewaySecretBroker.swift:26-98`），App 内的供应商凭证为 0600 权限的隔离文件。

注册中心元数据统一持久化于：
`~/Library/Application Support/Tomo/connections-v1.json`（当前模式版本 Schema V4），包含连接列表、启用状态及用户自定义的拖拽排序数组 `connectionOrder`。

## 2. 各供应商连接与认证

### 2.1 Codex (OpenAI)

#### 认证流程
1. **OAuth 2.0 PKCE 模式**：
   - 授权端点：`https://auth.openai.com/oauth/authorize`
   - Token 端点：`https://auth.openai.com/oauth/token`
   - Client ID: `app_EMoamEEZ73f0CkXaXp7hrann`
   - 回调地址：`http://localhost:1455/auth/callback`
   - 申请 Scope: `openid`, `email`, `profile`, `offline_access`。
2. **多账号隔离运行环境**：
   - 每个额外添加的 Codex 账号会被分配独立的 UUID 目录：
     `~/Library/Application Support/Tomo/Runtimes/Codex/<UUID>/`
   - 目录内自动生成 `config.toml`：
     ```toml
     cli_auth_credentials_store = "file"
     ```
   - 账号登录通过设置环境变量 `CODEX_HOME` 指向该隔离目录，执行 `codex login status` 或写入 `oauth_token.json`，实现完全隔离的会话与 Token 轮换。

#### 额度数据解析
Tomo 并行或顺序请求以下后端接口（统一设 60s 宽容超时，以适应代理网络）：
- `https://chatgpt.com/backend-api/wham/usage`: 获取当前 5 小时会话窗口 (`primaryWindow`) 与周维度窗口 (`secondaryWindow`) 的使用率百分比、重置倒计时（`resetAt`）。
- `https://chatgpt.com/backend-api/wham/rate-limit-reset-credits`: 获取限流重置额度券信息。
- `https://chatgpt.com/backend-api/subscriptions`: 获取用户的订阅层级（如 Plus、Team、Pro、Enterprise）。

### 2.2 Google Gemini (Antigravity)

#### 认证与回调
- 采用 Google Desktop PKCE OAuth 流程（`GeminiOAuthService.swift:192-194`）：
  - 授权端点 `https://accounts.google.com/o/oauth2/v2/auth`，token 端点 `https://oauth2.googleapis.com/token`。
  - Scope: `https://www.googleapis.com/auth/cloud-platform` 等（`:201`）。
- OAuth client ID 由编译期打包的 `GeminiOAuthConfig.plist` 提供，也可用环境变量 `TOMO_GEMINI_OAUTH_CLIENT_ID` 覆盖（`GeminiOAuthConfiguration.resolve`，`:113-146`）。缺配置时报「此版本未包含 Gemini 登录配置」（`:88-89`）。
- 本地回调服务监听 **随机可用端口**、路径 `/`：`http://127.0.0.1:<port>/`（`GoogleOAuthCallbackServer`，`:246`、`:837-838`），等待授权码超时 300 秒（`:276`）。
- 授权成功后 exchange code → 拉取 userinfo（email/name/picture）→ token 存 `~/Library/Application Support/Tomo/gemini_oauth/<handle>.json`，authorizationProfile 标记 `tomo-google-desktop-v1`（`:6-28`），用于区分旧版/他方签发的凭证（`purgeLegacyGeminiCredentials`，`MultiAgentSettingsStore.swift:103`）。

#### 额度与模型同步
Gemini 集成对接 Antigravity 的 Cloud Code 控制面（`https://daily-cloudcode-pa.googleapis.com`，`:199`，代码注释明确 `cloudcode-pa` 公共端点返回不完整故用 daily host）：
1. **账号计划**：`loadCodeAssist` 解析 project ID、current/paid/allowed tiers 与 ineligible 原因（`:637-658`）。
2. **额度桶解析**（`AntigravityRemoteQuota.parse`，`:671-720`）：从 groups/buckets 提取四类剩余比例——Gemini 周度、Gemini 5 小时、第三方（Claude/GPT）周度、第三方 5 小时，以及 reset 时间描述。
3. **可用模型**：`availableModels` 端点返回账号授权模型清单（`:661-669`）；`validateModels` 用于登录时验证（`:391`）。
4. **token 刷新**：过期前自动 `refreshToken`（`:292`）；限流错误会携带建议等待秒数（`rateLimited(Int?)`，`:102-106`）。

### 2.3 DeepSeek

- **添加方式**：在设置界面「账号与连接」中输入 API Key，可自定义连接标签（Label）。
- **Key 存储**：保存在独立目录 `~/Library/Application Support/Tomo/deepseek_credentials/<handle>.json`，文件属性强制 `0600`。
- **余额查询**：
  - 端点：`https://api.deepseek.com/user/balance`
  - 请求头：`Authorization: Bearer <API_KEY>`
  - 解析字段：`currency`（通常为 CNY/USD）、`total_balance`、`granted_balance`、`topped_up_balance`。
- **可用模型验证**：
  - 端点：`https://api.deepseek.com/models`
  - 返回官方模型列表（如 `deepseek-chat`、`deepseek-reasoner`），同时校验 Key 的合法性。

---

### 2.4 OpenCode (Zen / Go)

- **支持方案**：
  - `OpenCode Zen` (端点: `https://opencode.ai/zen/v1/models`)
  - `OpenCode Go` (端点: `https://opencode.ai/zen/go/v1/models`)
- **存储**：保存在 `~/Library/Application Support/Tomo/opencode_credentials/<handle>.json`，与 DeepSeek 凭据物理目录隔离，防止 handle 碰撞。
- **验证与发现**：通过调用模型目录端点完成轻量校验与可用模型抓取。

## 3. 额度刷新机制与账号轮播

### 3.1 统一刷新（performUnifiedRefresh）
刷新入口收敛为一个「统一刷新」流程（`AppDelegate.swift:253-287`）：
1. **防重入**：`isUnifiedRefreshing` 期间再次触发会提示「正在刷新，请稍候」。
2. **全量并发**：`MultiAgentSettingsStore.refreshAllConnections()` 先把全部四类连接登记为 `refreshingConnectionIDs`（UI 可按账号单独显示加载态），然后每个连接一个并发 Task，逐个完成、结果 `merge` 成 `RefreshOutcome(failures:[...])`（`MultiAgentSettingsStore.swift:224-280`）。
3. **联动**：刷新成功后顺带执行 `GatewayStore.syncConfiguredAgentCatalogsIfNeeded()` —— 官方模型目录变化时才更新 Hermes/Pi 的模型白名单（`AppDelegate.swift:272-274`）。
4. **触发时机**：
   - 启动静默刷新（不改变刘海按钮结果态，`AppDelegate.swift:222-226`）。
   - 定时器：`AutoRefreshInterval` = 30 秒 / 1 分 / 2 分 / 5 分 / 10 分 / 关闭（默认在设置「通用」页调整）；手动刷新后会**重置倒计时**，等本轮加载结束再重新计时（`AppDelegate.swift:236-241, 281-282`）。
   - 手动点击刷新/登录按钮。
5. **刷新 vs 登录的语义**：只要存在任何连接，「刷新」按钮就做统一刷新；完全无连接时按钮升级为「登录」，走 `addCodexAccount()` 的 OAuth 流程（`AppDelegate.swift:109-117, 228-251`）。
6. **Codex 刷新细节**：token 过期余量 <60s 先自动 refresh（`CodexUsageService.fetchWithStoredToken`，`CodexUsageService.swift:65-77`）；额度、可用模型分两路拉取；**禁用（proxy 关闭）的账号跳过刷新且保留真实登录态**，防止被误标为 needsLogin（`MultiAgentSettingsStore.swift:287-300`）。
7. **快照缓存**：`UsageSnapshotCache` 落盘最近一次成功快照供冷启动秒显（`UsageModels.swift:269-307`）。

### 3.2 账号轮播 (Account Carousel)
多连接时在三个表面轮播展示（间隔 `AccountCarouselInterval`：关闭 / 5 秒 / 10 秒 / 30 秒 / 1 分钟，`AppSettings.swift:84-106`）：
- 主窗口供应商 logo 行（独立开关 `mainWindowProviderCarouselEnabled`）。
- 刘海面板供应商卡（独立开关 `notchProviderCarouselEnabled`）。
- 轮播顺序 = `orderedConnectionKeys`（支持用户拖拽排序的 `connectionOrder`，`AccountConnectionServices.swift:11-12`）。
- **暂停语义**：`AccountCarouselPauseSource` 多来源集合（仪表盘 hover、编辑弹窗…），任一来源暂停即停，全部恢复才续播（`MultiAgentSettingsStore.swift:131-145`）。
- 点击当前 logo 也会重启计时（`AppDelegate.swift:153-157`）。

## 4. 连接管理操作

在设置 → 「账户池」页（`AccountConnectionsSettingsView.AccountConnectionsModalView`）：

| 操作 | 实现 |
|---|---|
| 添加 Codex 账号 | `addCodexAccount()`：创建隔离 CODEX_HOME → 浏览器 OAuth（PKCE，回调 `localhost:1455`，超时 90s）→ 拉额度与模型（`MultiAgentSettingsStore.swift:409-471`，`CodexUsageService.swift:142-210`） |
| 重新授权指定账号 | `authenticateCodexAccount(_:)`（`:472`）；OAuth 等待中可取消 `cancelCurrentCodexOAuth()`（`:403-407`） |
| 添加 DeepSeek / OpenCode / Gemini | Key 输入弹窗，保存时即调用 `/models` 或 `/user/balance` 验证（`AccountConnectionServices.swift:302-330, 420-471`） |
| 删除 / 退出 | `removeCodexAccount` 连运行目录一起删（`AccountConnectionServices.swift:159-167`）；`disconnectSelectedConnection` 仅清 token 置 needsLogin（`MultiAgentSettingsStore.swift:533-554`） |
| 启用/停用路由 | `toggleConnectionProxyEnabled(id:)`：停用=不参与网关路由与额度刷新（`:556-600`） |
| 查看明文 Key | 需通过 macOS 系统认证（Touch ID / 登录密码，`LAPolicy deviceOwnerAuthentication`，`APIAuthRevealService.swift:34-63`），UI 见 `APIKeyRevealModal`（`SettingsViews.swift:2485`） |
| 连接健康状态 | `ConnectionAuthenticationState`: connected / needsLogin / checking / invalid（`MultiAgentModels.swift:148+`）；余额指示 `ProviderBalanceIndicator`、额度健康 `QuotaHealthLevel`（`UsageModels.swift:406`）驱动颜色（跟随额度绿/黄/红） |

## 5. Codex API 探测（CLI）

`CodexAPIProbe`（`CodexAPIProbe.swift`）配合入口 `--probe-chatgpt-apis`：以当前登录态向 ChatGPT backend 的一组候选端点发起请求，记录 `HTTPRecord`（状态、字段命中 `FieldHit`）并汇总 `SessionManifest`，产物落盘为目录 + `manifest.json`，用于维护者追踪官方 usage 接口字段变化（`ApplicationMain.swift:12-15`、`CodexUsageService.swift:338`；脚本 `scripts/run_chatgpt_api_probe.sh`）。

## 6. 常见问题排查

- **Gemini 提示「OAuth 凭证不可用 / 授权已过期」**：token 续期失败。到「账户池」对该 Gemini 连接重新登录；上游网络异常（代理 400/连接失败）也会导致校验失败，先确认直连可用。
- **Codex 提示「未找到 codex CLI」**：Tomo 依次探测 `/opt/homebrew/bin/codex`、`/usr/local/bin/codex`、`~/.local/bin/codex`，再回退 `zsh -lc "command -v codex"`（`AccountConnectionServices.swift:169-194`），确保终端可执行 `codex`。
- **DeepSeek/OpenCode 提示 Key 无效**：401/403 → Key 被撤销或不属于该计划（OpenCode Go 与 Zen 的 Key 与端点绑定，`AccountConnectionServices.swift:455-459`）。
- **旧版 Key「interactionRequired」**：旧版本签名保存的 Keychain 条目无法解密，需重新添加（`:213`）。
